# 错题园丁 / Mistake Gardener

> 会自己出题的英语打字陪练 — An English typing coach that writes its own drills from your mistakes.

一个英语打字练习系统，加上一条由 AI agent 跑通的闭环：**把每一次敲错的原始按键流，变成下一轮要练的词库**。

上游是 [Qwerty Learner](https://github.com/RealKai42/qwerty-learner)（GPL-3.0，单词记忆与英语肌肉记忆锻炼软件）。本项目是它的衍生作品：在官方构建之上打了五项补丁、重写了判定规则与长句排版、接了一个会归因的生成端，并把整条链做成可重放的脚本。

---

## 1. 它解决什么

打字练习的老问题是两件事：练完不知道错在哪，也不知道下一轮该练什么。

1. **错在哪**：只记"错了几个"没有用。这里记录每个字符的击键间隔、错位位置、打错的字符，然后按错误类型归因（空格处理 / 跳字串位 / 回跳 / 真键位错）。
2. **练什么**：错题不是被统计，是被养成词库。按错误密度筛错词（零错的词会被剔除），按历史出错位置的覆盖面切练句，释义回查站点自带词典，然后**自动同步站点里的章节元数据**，刷新页面就能练到新内容。

## 2. 三个可验证的差异点

1. **判定规则由数据定，不靠感觉**。归因显示 42 个错误事件里空格处理占 23.81%，而**纯标点位置错误 0 例**。于是判定改成"只罚真错"：目标串里的空格与标点由程序自动判对，用户敲出来的空格标点直接忽略，只有字母数字打错才算错。同时留了一个"空格必打"严格开关（默认关），防止练废空格习惯。
2. **长句不打结**。官方布局会把 62 字符的整句从单词中间劈开（`...must feel b` / `oth free...`）。这里改成按词分组、组内不换行，换行只发生在词间；字号按条目长度分档缩放（>80 字符 → 0.46 倍，>56 → 0.55，>40 → 0.68，>24 → 0.82），整句压到一行。
3. **闭环自证**。改完不是靠"我看了一眼"，而是 agent 驱动真实浏览器把整章打完并断言：漏打标点空格也判对、严格模式下判错、末字母打错仍判错、单词类行为未变。回归脚本会 dump 字母分组、行数、IndexedDB 记录与 console 报错。

## 3. 闭环五步（每一步都有脚本）

| 步骤 | 脚本 | 产物 |
|---|---|---|
| 采数据 | 页面注入的 `__mistakeReporter` | 结构化按键流水（间隔 / 错位 / 错字符） |
| 做归因 | `agent/qwerty-mistake-analysis.md` 对应的分析流程 | 归因报告（含"数据不支持某某改动"这类反向结论） |
| 自动出题 | `agent/qwerty-dict-from-mistakes.py` | 错词本 + 句子库 JSON，并同步站点元数据 |
| 口径校验 | `agent/qwerty-replay-check.py` | 把新判定回放到历史数据，核对改动的真实影响面 |
| 自证 | `agent/qwerty-e2e.py` | 浏览器端到端回归 + 截图 |

排序原则写在脚本里，可复算：错词按"事件 / 必打字符数"的密度与尝试次数筛；句子按各切片覆盖的历史出错位置数排序；空格与标点上的历史错误不再参与统计（因为新判定下它们不算错）。

**一个容易被忽略的点**：改判定必须同时改统计口径。本项目第一版生成端还在用旧口径算密度，等于"继续为已经不存在的错误类型出题"，重放脚本发现后改为"新判定下仍算错"的口径并重跑。

## 4. 真实数字（样本小，如实标注）

基于 36 条真实练习记录、42 个错误事件：

1. 空格处理 10 / 42 = 23.81%；纯标点位置错误 0 / 42。
2. 互斥分类：跳字串位 14 + 回跳 5 = 45.24%，真键位错 13 = 30.95%，空格 10 = 23.81%。
3. 最强单词信号：`n → m`（numerous 首字母，占单词类事件的 26.7%）。
4. 新判定回放：16 条有错记录 → 12 条仍错、4 条转为无错；句子类 6 条有错 → 4 条转无错、2 条仍错（都是真键位错）；事件 42 → 32，豁免 10 个。

样本量小，所有结论都标了口径（事件口径 / 位置口径 / 记录口径）。

## 5. 目录结构

```
patches/   在官方构建产物上打补丁的脚本（每处替换都断言唯一 + node --check 后才落盘）
agent/     归因报告、词库生成器、判定重放校验、浏览器端到端回归
server/    静态与接口服务（含语音合成路由、缓存策略、按来源分流错题数据）
docs/      运维手册（写给下一个接管者的：端口、机制、踩坑、回滚、自检清单）
```

## 6. 快速开始

1. 取上游 gh-pages 构建产物作为基线，部署为静态站。
2. 打补丁：`python3 patches/qwerty-bundle-patch.py`（脚本头注写了基线要求与五项改动）。
3. 服务端：`server/` 下的参考实现提供静态托管、`POST /collect`（错题上报）、`GET /tts`（语音合成）。
4. 端到端验收：`python3 agent/qwerty-e2e.py --help`，用 `--mode both`（不打标点空格）验证放宽判定，用 `--strict` 验证严格开关。
5. 出题：`python3 agent/qwerty-dict-from-mistakes.py` 先 dry-run 看选词依据，加 `--apply` 落盘。

详细机制与踩坑记录见 `docs/`，里面有若干"看起来该这么改但其实会坏"的实测结论（例如给 ESM 构建产物的引用加 `?v=` 查询参数会让同一模块以两个 URL 加载、React 出现双实例白屏）。

## 7. 已知限制

1. "打错一个字母就清空整条"是上游的固有行为，本版本未改；长句重打成本偏高，分段条目缓解了一部分。
2. 最小对比对词库（`bean/beam`、`cite/site`、`contract/contrast` 等治 `n → m` 的对比组）尚未落地。
3. 错误事件样本仍小（42 个），判定阈值适合继续观察后再调。
